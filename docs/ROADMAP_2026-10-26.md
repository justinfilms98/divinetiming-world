# Divine Timing — roadmap after Phase 0 (2026-10-26)

Companion to `AUDIT_PHASE0_2026-10-26.md`. Nothing here is implemented unless marked done.

## Standing rules

- **Mobile first.** Every phase is designed and tested at 360–390px first, then 768px and 1440px.
  - Acceptance needs mobile + desktop screenshots, and throttled-network measurements (LCP, CLS, bytes, time to first video frame).
  - Real iOS Safari and Android Chrome checks are done by a person on a phone; emulation alone doesn't pass a phase.
- **Security lockdown stays.** Migrations 054–056 are never relaxed to make a feature work. New writes go through server routes using the service role after `requireAdmin()`.
- **Placeholder content is preserved.** The test collections, the seven events and the test product are owner-made demos. Hide them, don't delete them. Archive only after real content is published and the owner decides.
- **Payments dependency.** Branch `fix/rls-lockdown` (webhook and checkout use the service client) must be deployed before Stripe is activated.

## Newsletter assessment

### What exists today

- **Signup form.** `TribeSection` on the homepage collects email plus optional first name and country.
  - Works on mobile: 48px targets, 16px inputs.
  - No consent text, privacy link or honeypot.
- **Table.** `subscribers` has unique `lower(email)`, `status` (subscribed / unsubscribed / bounced), `segment` and `source`. There are 0 rows.
  - Reads are admin-only (054).
  - Anonymous REST insert is removed by 057, pending deploy.
- **API.** `/api/subscribe` validates, lowercases and swallows duplicates without revealing whether an address exists.
  - Service client, length caps and honeypot are on `fix/rls-lockdown`.
  - Re-subscribing after an unsubscribe silently does nothing.
- **Email.** `lib/email/notify.ts` calls the Resend REST API directly (no SDK) with `RESEND_API_KEY` / `RESEND_FROM`. It's used only for booking emails. Resend isn't configured in production yet.
- **Missing.** Unsubscribe, consent record, double opt-in, welcome email, admin list or export, and the `List-Unsubscribe` header.
- **Dead code.** `components/home/SubscribeSection.tsx` is a fake form that isn't imported anywhere; delete it.

### Recommended approach

Extend what's there: Supabase table plus the existing Resend helper. No new vendor.

The operator is a Spanish autónomo, so GDPR/LSSI apply. That means explicit consent, a stored consent record, easy unsubscribe, and **double opt-in recommended**. Double opt-in also cuts fake or abusive signups and protects sender reputation.

### N1 — Basic subscriptions (launchable alone): about 2–3 days

- **Migration:**
  - Add `consent_at`, `consent_text`, `confirmed_at`, `unsubscribed_at`, `confirm_token` (hashed), `unsubscribe_token` (hashed) and `signup_ip_hash`.
  - Add an `updated_at` trigger.
  - Status adds `pending`.
- **Form:**
  - Consent line plus privacy link under the button.
  - Hidden honeypot field.
  - Clear mobile states ("Check your inbox to confirm").
- **API:**
  - Upsert, so an unsubscribed or pending address can re-join.
  - Simple per-IP-hash and per-email throttle stored in Postgres.
  - Send a confirmation email. The confirmed page doubles as the optional welcome.
- **Routes:**
  - `/subscribe/confirm?token=` and `/unsubscribe?token=`: one tap, no login, mobile-friendly.
  - `List-Unsubscribe` and `List-Unsubscribe-Post` headers on every list email.
- **Admin "Community" page:**
  - Subscriber count and growth.
  - Search and status filter.
  - Manual unsubscribe.
  - CSV export.
  - Mobile card list, not a table.
- **Email templates:** a single-column 600px-max layout that reads well on phones. Same brand: night background, gold, spiral.

### N2 — Campaigns (separate launch): about 4–6 days

- **Tables:** `newsletter_campaigns` (draft / scheduled / sending / sent), `newsletter_sends` (per-recipient status), and campaign templates for Release, Show, Announcement.
- **Composer:**
  - Pick a template, pull in a release or event from the site, write text, preview on mobile and desktop.
  - Send a test to yourself, then send to a segment.
- **Sending:**
  - Server-side batches using Resend's batch endpoint, resumable if interrupted, with per-recipient unsubscribe links.
  - Bounce and complaint webhook marks addresses `bounced`.
- **Separate from site publishing:** separate button, separate permission, separate confirmation.

### Operating cost

Resend pricing should be re-checked at signup.

- **Free tier:** about 3,000 emails/month and 100/day. That covers N1 and small campaigns. Daily caps limit large sends.
- **Paid tier:** about $20/month for roughly 50,000 emails/month, once the list outgrows the free tier.
- **Required, free:** verify `divinetiming.world` in Resend (DNS records SPF/DKIM, plus DMARC recommended). That's a DNS change, so it needs owner approval.
- **No other services.** Supabase and Vercel usage is negligible.

## Creative Dashboard — architecture assessment

### Current admin

The admin has 17 sections. All are large client-component pages; the biggest are shop at 937 lines, the hero editor at 857 and collections at 831. They sit in a desktop sidebar that collapses to a 56px unlabeled icon rail on phones.

Problems on a phone:
- About 287px of usable width at 375px.
- Hover-only delete buttons and 20–28px tap targets.
- Fixed `min-w` fields, with the overflow hidden by `overflow-x-hidden`.
- About 15 browser `alert()`/`confirm()` calls.
- No preview or draft mode, and no drag-and-drop.
- The admin's own dark theme in `admin/admin.css` is separate from the site tokens.

All data access already goes through `/api/admin/*` with `requireAdmin()` and the service role. That's the right foundation: the dashboard is a UI rebuild over existing APIs, not a new backend.

### Approach

- **Keep:** Next.js App Router, Supabase, the existing API routes, `UniversalUploader` (extended) and the existing brand tokens.
- **Mobile shell:**
  - Bottom tab bar: Home, Media, Content, Community, More.
  - Content groups Collections, Events, Music, Journey and Press. More holds Shop, Hero, Settings and Legal.
  - Desktop keeps a labeled sidebar. Sections move under the shell without changing their URLs.
- **Shared primitives** replace per-page modals:
  - `Sheet`: bottom sheet on mobile, dialog on desktop.
  - `StatusBadge`, `ConfirmSheet` (replaces `confirm()`), sticky `ActionBar` (Save draft / Preview / Publish) and `EmptyState`.
  - Built on existing CSS variables, so the admin uses the site's night/sand/gold.
- **Preview:** Next.js `draftMode()` behind `requireAdmin`, so drafts render on the real page for admins only. Public queries and RLS stay published-only.
- **Reordering:** `@dnd-kit` (MIT, about 10 KB, touch and keyboard support, no subscription) is the only proposed new dependency. The alternative is hand-rolled pointer events, which is more work and less accessible.
- **Roles:**
  - `admin_users.role` becomes `owner | editor | contributor`.
  - `requireAdmin({ can: 'publish' })` enforces it server-side, and contributors can only save drafts.
  - Activity goes to the existing `content_audit_log`.
  - Revisions go to a `content_revisions` snapshot table, with restore where practical.
- **Credentials:** stay server-side only (service role, Resend, Stripe, GitHub). The browser keeps only the anon key.

**Total:** about 18–23 days for the dashboard plus 6–9 days for newsletter. D2 and D3 also deliver the brief's publication-controls and photo-ratio phases, so that work isn't counted twice. D0 should land before D2 so new screens are built mobile-first.
